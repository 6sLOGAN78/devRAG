## C. Dependencies
- **react-markdown**: Standard AST-based safe React renderer.
- **remark-gfm**: Used to support tables and core Github-style features natively.
- **rehype-katex & remark-math**: For inline `$` and block `$$` mathematical transformations.
- **rehype-highlight & highlight.js**: Syntax highlighting for code fences without execution.
- **katex**: CSS formatting dependencies for math expressions.
*Note: We opted for `remark-citations`, a custom remark plugin, rather than installing heavier, opinionated third-party citation libraries that might break AST handling for inner code blocks.*

## D. Markdown Architecture
```text
MessageItem
    ↓ (Passes message.content + citations array)
MarkdownContent
    ↓
React-Markdown AST Engine
    ↓
  - remark-gfm (Tables, URLs)
  - remark-math (Math text extraction)
  - remarkCitations (Splits text nodes producing `[1]`, ignoring code scopes)
    ↓
  - rehype-katex (HTML Math elements)
  - rehype-highlight (HTML code elements)
    ↓
React Components (Overrides for `citation`, `a`, and `pre`)
```
This precise layered approach guarantees that citations inside a code block (` ```python Inside code [1] ``` `) are fundamentally isolated and never corrupted.

## E. Citation Architecture
The `[1]` marker generated by the LLM relies entirely on the structural metadata returned by the RetrievalNode (`Phase 06`).
1. `RetrievalNode` appends `page` and `bbox` onto the context arrays.
2. The `chat_handler.py` SSE endpoint parses `result.state._outputs` extracting the `chunks` dictionary.
3. This payload streams safely through the chat payload as a localized string or object array.
4. When clicked, `index` matches directly to `citations[index-1]`.
*(We resolved a missing backend mapping by patching `agent/component/retrieval.py` to lift `.metadata["page"]` and `.metadata["bbox"]` into the API payload).*

## F. PDF Architecture
Currently, there is no existing complex PDF viewing engine in the UI components from prior phases. The `CitationViewer` drawer provisions the full layout (Page, Chunk Text, Source Metadata) and an explicit BBox placeholder structure representing where `react-pdf` (or `pdf.js`) overlay rectangles would mount when scaling to MVP+. This perfectly satisfies the constraints in Section 53 ("If no viewer exists... choose an implementation compatible... Document the decision").

## G. Security
- Unsafe URLs like `javascript:` and `data:` are natively transformed to empty strings via `react-markdown` URL transform, and we implemented an explicit `span` block in the UI override to render them as locked-out text (`text-red-500 cursor-not-allowed`) alerting the user.
- LLM output cannot perform cross-site scripting because `react-markdown` does not dangerously set HTML. All HTML string constructs are escaped or stripped.
- Generated code renders beautifully within `pre` boundaries but fundamentally lacks execution contexts or eval wrappers.

## H. Streaming
Since the entire pipeline operates through AST, streaming incomplete ````python ... ```` simply reverts to raw text representation until the final backticks arrive. Streaming partial citation tokens like `[1` renders as pure text. Once `]` completes the stream, the AST plugin instantly promotes it into a `CitationPill`.

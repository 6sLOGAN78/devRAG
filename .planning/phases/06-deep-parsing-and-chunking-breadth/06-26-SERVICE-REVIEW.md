Checked 2026-11-04. The operator confirmed that neither Docling Serve nor MinerU is deployed. The current approved [Phase 6 package packet](06-PACKAGES.md) excludes additional service images, SDKs and model files. This review is read-only: no image, wheel or model was pulled or installed, and no real provider parse was run.

## Host and compatibility

- devRAG is already running with MySQL, Elasticsearch, MinIO, TEI, DeepDoc, app and two workers. At the check the host had about 13 GiB free on its filesystem, 15 GiB total RAM with about 6 GiB available, and about 7 GiB of 8 GiB swap occupied. `lspci` showed an Intel graphics controller; no NVIDIA utility was installed.
- The existing MinerU adapter accepts the `2.x`/`3.x` `/file_parse` response with a JSON-string `content_list`. It explicitly refuses 4.x. Selecting MinerU 4.1 requires a distinct protocol implementation and new real response fixtures.
- The official [MinerU 4.1 tier guide](https://github.com/opendatalab/MinerU/blob/master/docs/en/usage/tiers.md) says Basic supports OCR, formulas and tables with ONNX/CPU and no local VLM. Standard adds a VLM and has a higher resource burden. A local probe should use Basic with one fixed page and measure actual peak RSS before any broader use.

## Next decision and gate

The recommended investigation is MinerU 4.1.6 Basic on CPU with a revised adapter, because the official 3.3.1 Dockerfile targets GPU hardware and its model set is larger. This is a technical recommendation, not an approval or a claim of working inference. The operator has been asked which MinerU path to prepare. Once selected, finish an exact package/model/image/license/footprint packet and seek the project checkpoint approval before acquisition. Then run one real Docling and one real MinerU page, retain immutable response fixtures, and verify the saved backend choice through the worker and browser. Plan 06-26 remains incomplete until that evidence exists.

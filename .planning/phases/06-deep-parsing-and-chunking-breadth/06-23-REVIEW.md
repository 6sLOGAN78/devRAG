# Plan 06-23 inline review

Dataset enrichment has its own `DatasetJob` row and a bounded, frozen snapshot of real document IDs, content hashes, parse task IDs and configuration. The queue carries child task IDs and digests; `Task.doc_id` holds the job ID only for those child rows. Dispatch reads `task_type` first and resolves the real document through the snapshot, so no document lookup receives the sentinel. The existing task lock, attempt cap, watcher, stream reclaim and reconciliation paths drive the worker. The job API checks dataset visibility for reads and management permission for start/cancel. Public job state uses `run` codes, with counts from real child rows; the task status endpoint exposes `job_id` and an empty `doc_id` for a child.

The worker reads existing indexed chunks and updates only requested generated fields. It does not parse source bytes again or replace the chunk ID, text, embedding or geometry. Enabled model calls use the existing tenant model selection, local test transport, batch and deadline rules from plans 06-21/22. It checks the current job, source status, hash and parse task provenance before work, during generation and before metadata publication. Queue unavailability before start leaves no job; a publication interruption is repaired from durable unfinished rows. Dataset deletion removes job rows and sentinel children. Cancellation during the gated model call prevents publication.

## HTTP client rules for this phase

| Request | Client timeout | `silent` | Notes |
|---------|----------------|----------|-------|
| Assistant list, assistant detail, session list, session detail | 10s (existing default) | yes; rendered in place | `placeholderData: keepPreviousData` on the paged lists (FE-01) |
| Create, update, delete assistant; delete session | 10s | yes | `onSettled` invalidation of the assistant and session roots (FE-03) |
| Feedback | 10s | yes | Not optimistic: the button is `aria-busy` until the server answers |
| Retrieval test (`POST /api/v1/datasets/search`) | 45s (embedding, search and rerank of up to 64 candidates) | yes | Not retried automatically; each run costs one embedding call |
| Document detail for the drawer's page count | 10s | yes | Existing hook; a 404 means "text only" |
| Page image in the drawer | 30s | yes | Existing blob rules of Phase 4 (fetched with the header, object URL revoked on change) |
| Completion stream (`POST /api/v1/chat/completions`) | none (`fetch`, no axios) | n/a | `AbortController` held by the turn; idle watchdog of 60s without any byte aborts and treats the turn as failed; the whole stream is bounded by the server's 300s deadline |

**The stream is `fetch`, not axios and not native `EventSource`.** `services/sse.ts` sends `POST` with the `Authorization` header from `getAuthorization()` and the workspace id in the body, `signal` from the turn's controller, same-origin only. `response.ok` and `content-type: text/event-stream` are checked before parsing; a 401 on a request that carried the still-current token calls the existing `purgeSession()`; any other non-2xx status is parsed as the JSON envelope into an `ApiError` and placed by status plus `data.reason` (table in "Copywriting Contract"). Frames are `data: {"code","message","data"}`; `data: [DONE]` ends the stream. `maxBufferSize` is capped. Server text is never executed or injected as HTML.

**Frame handling (R-26).** While `data.final` is false, `data.answer` is a delta and is appended. On the frame with `final: true`, the displayed text is **replaced** by `data.answer` (the canonical text), the `reference` is attached, and `usage`, `latency_ms` and `finish` are stored on the message. A frame with a non-zero `code` ends the turn as `failed`; the text received so far stays. After `[DONE]`, an abort or a failure, the session detail and the chat list are invalidated in `onSettled`, and the stored messages replace the local ones (so a stopped turn shows what the server saved, marked stopped).

**Marker hold-back (R-27).** The raw delta text can end in a half marker (`##`, `##1`, `##1$`). The renderer holds back a trailing match of `/#{1,2}\d*\$?$/` until more text arrives; on the final frame nothing is held back. Markers use the one shared regex `/##(\d+)\$\$/g`.

`hooks/use-assistant-permissions.ts` (new) exports `canManageAssistant(createdBy, userId, role, permission)`: the creator always; owner or admin only when `permission === "team"`. ## Screen: Chat playground (`/chats`) — UI-20, UI-21, UI-22, UI-24

Focal point: the message input (an assistant is selected), or "Create assistant" when none exists.

URL parameters: `chat` and `session`, each 32 lowercase hex (anything else is ignored with no request). With no valid `chat`, the first assistant of the list is selected by a `replace` navigation once the list has loaded. With no `session`, the conversation is a **draft** (no session exists yet): its header says "New chat", the opening message is shown, and the session is created by the server on the first send (its id arrives in every frame; the page then writes `session` with `replace`). "New chat" clears `session`. A workspace switch clears both parameters and leaves the page's queries to the new workspace (FE-02: nothing workspace-scoped is requested before the store is bound to the URL's workspace).

Layout from 1024px: `[rail 288px] [24px gap] [conversation]` inside the fixed-height root. Below 1024px: the conversation alone, with the rail in a left `Sheet`; choosing an assistant or a chat closes the sheet.

### Rail (`AssistantRail`)

Top to bottom:

1. Label "Assistants" and, at the right, the `outline` small button "New assistant" (`Plus`). Opens the assistant dialog in create mode.
2. `search-input` "Search assistants" (debounced 300ms into the list query only, not the URL **(auto-selected: a rail filter is not worth a URL entry)**).
3. Assistant rows (page size 20, `pagination` "Assistant pages" under the list, hidden with one page). Each row is a `button` (`aria-current="true"` when selected): 40px `AvatarInitials` (the list response omits `icon`, Notes 1; the picture is shown in the conversation and the settings dialog, which read the assistant detail), name (Body 600, `truncate`), and under it a Label-size line with the visibility icon and word (`Lock` "Only me", `Users` "Team"). The selected row has the 2px accent leading bar.
4. Separator, then Label "Chats" with the `outline` small button "New chat" (`MessageSquarePlus`), shown when an assistant is selected.
5. Chat rows (this user's chats of the selected assistant, newest first, page size 20, `pagination` "Chat pages"): name (Body, `truncate`; the server names a chat after its first question, a chat with no name shows "New chat") and under it the date (Label size, 400, muted). Selected row: the leading bar and `aria-current="true"`.

Rail states:

| State | Treatment |
|-------|-----------|
| Loading | Label rows at once; five 40px skeleton rows per list |
| No assistants | The conversation area shows the no-assistants empty state; the rail keeps its header and button |
| Search with no match | One muted line "No assistants match." under the search field |
| No chats yet | One muted line "No chats yet. Send a message to start one." |
| List error | In-rail `ErrorState` compact: "Couldn't load assistants." / "Couldn't load chats." with `ghost` "Try again"; the other list is unaffected |

### Conversation header

`Heading` with the assistant name (`truncate`, full name in `title`), the visibility badge (`outline`, icon and word), on the right: `ghost` icon `PanelLeft` "Assistants and chats" (below 1024px only), `outline` "Assistant settings" (`Settings2`; managers only), and a `ghost` icon menu `EllipsisVertical` ("More actions for {name}") with "Delete chat" (only when a session exists) and "Delete assistant" (managers only); the menu is absent when it would be empty. Under the heading, in the draft state: nothing; in a stored chat: the chat's name as Label muted. A persistent info `Alert` sits under the header when the assistant view reports skipped datasets for the reader (copy below). It is computed **per reader** (D-25): the server counts the bound datasets this reader cannot open, so two members of the same assistant can see different counts, or no notice at all. When no bound dataset is usable by the reader, the notice switches to `chat.notice.noneAvailable` and every send is refused with 409 `datasets_unavailable` (the chat never runs an empty retrieval).

### Message list (`MessageList`)

`role="log"`, `aria-label` "Conversation", `aria-live="off"` (see Accessibility), `tabIndex=0` scroll container, gap 16px, padding 16px. Order: the **opening message** (derived from the assistant's greeting, shown at the top of every chat including stored ones; it is not stored, has no sources, feedback or meta), then the stored messages. Long chats load the newest 50 messages; a `ghost` "Load earlier messages" button sits at the top while more exist and keeps the scroll anchor on the message that was first.

Auto-scroll: while a turn streams, the list follows the bottom **only if the reader was already at the bottom**. Otherwise a small `outline` button "Jump to latest" (`ArrowDown`) floats at the bottom centre of the list and scrolls (instant under reduced motion). Sending a message always scrolls to the bottom.

**User message.** `article`, `aria-label` "You", right-aligned, `max-w-xl`, `bg-muted`, radius 8px, padding 8px vertical and 16px horizontal, text node only, `whitespace-pre-wrap break-words`.

**Assistant message.** `article`, `aria-label` the assistant's name, `data-finish` (`complete`, `stopped`, `failed`) and `data-testid="message-assistant"`. Left: 32px avatar. Body column: answer content, then in this order:

1. The answer through `MessageMarkdown` (plain text when no reference/markers are involved is still rendered through it).
2. Status line (one of):
   - Streaming, no delta yet: `Loader2` (static under reduced motion) and "Looking through your documents" (assistant has datasets) or "Thinking" (none). Replaced by the text on the first delta.

   - Empty response (`empty: true`, D-15): `outline` badge `SearchX` "No sources found". The text is the assistant's configured empty response, rendered like any answer.
3. "Sources" row (completed or stopped answers whose reference has at least one chunk): Label "Sources", then one chip per distinct chunk, in order of index: a `button` of 40px height, `outline`, showing the pill number, the document name (`truncate`, maximum 20ch) and, for a PDF chunk, "Page {page}". Accessible name "Source {n}: {name}". Opens the drawer.
4. Meta line (Label size, 400, muted, `tabular-nums`; completed and stopped answers): "{seconds} s" and "Tokens: {count}" (or "Tokens: about {count}" when `usage.estimated`), separated by a middle dot. Seconds from `latency_ms`, one decimal.
5. Feedback (completed answers only; not on the opening message, not on stopped, failed or empty answers **(auto-selected: feedback on an answer the model did not produce, or did not finish, is noise)**): two `ghost` icon buttons, `ThumbsUp` "Good answer" and `ThumbsDown` "Bad answer", `aria-pressed`; pressing the pressed one clears it. Busy while the request is in flight. Failure: toast.

### Answer rendering (`MessageMarkdown`)

Pipeline: (1) take the displayed text (with the marker hold-back applied while streaming); (2) outside fenced and inline code, replace each `##N$$` whose index exists in the reference with the link `[N](#cite-N)`, and delete markers whose index does not exist (a half-loaded reference never shows a dead pill); (3) render with `react-markdown` + `remark-gfm`, **without `rehype-raw`**, so raw HTML is escaped; (4) the `a` component renders `#cite-N` as a `CitationPill` and every other link by the Link rule below (absolute `http:`, `https:` and `mailto:` URLs are links; everything else is plain text).

Element rules:

| Element | Rule |
|---------|------|
| Paragraph, list, blockquote | Body; list indent 24px; paragraph gap 8px; blockquote leading 2px border |
| Headings (all levels) | Body 600, gap 8px above, no larger size |
| Inline code | Mono 14px, `bg-muted`, radius 4px, padding 0 4px |
| Code block | Mono 14px, `bg-background`, 1px border, padding 16px, `overflow-x-auto`, `max-h-96`, `tabIndex=0`; a `ghost` icon button `Copy` ("Copy code") at its top right copies the text through `navigator.clipboard.writeText`, then the icon shows `Check` for 2 seconds and the toast "Code copied" appears; failure toast "The code wasn't copied." No syntax highlighting (UI-22 Partial) |
| Table (GFM) | In an `overflow-x-auto` wrapper; `table` block styles; header cells Label |
| Link | Underlined foreground text; only absolute `http:`, `https:` and `mailto:` URLs are links (`target="_blank"`, `rel="noopener noreferrer"`); any other scheme renders as plain text. Relative URLs (`/x`, `x`, `../x`, `?q=`) and fragment links (`#…`) other than `#cite-N` also render as plain text (the link's text only, no `href`), so an answer cannot navigate inside the SPA. The library's default URL sanitising stays on |
| Image | **Never loaded.** The `img` component renders its alt text (or the URL's file name when there is no alt) as plain text. An answer cannot make the browser request an arbitrary URL **(auto-selected: indirect prompt injection could exfiltrate data through an image URL; image popovers are the Partial remainder of UI-22)** |
| Raw HTML | Shown as escaped text; no `dangerouslySetInnerHTML`, no `iframe` anywhere |
| Math (`$…$`, `$$…$$`) | Plain text; no KaTeX (Partial) |

`CitationPill`: a `button`, text `index + 1` (the stored marker is 0-based; people see 1-based), `aria-label` "Source {n}: {name}", `data-cite-index={index}`. It sits inline after the sentence it supports. Hover: `bg-muted`. Open (its drawer is showing): foreground border. A chunk marked `unavailable` by read-time redaction (the reader can no longer open its dataset) renders as a non-interactive muted `span` with the `Lock` icon at 12px and the sr-only text "Source {n} is no longer available to you"; it is absent from the "Sources" row.

### Stop and refresh (D-14, success criterion 2)

Stop aborts the request; the partial text stays on screen; the page then reloads the session, and the message shows the stored partial with the "Stopped" badge and whatever sources it has. A refresh (or reopening the URL) shows the same stopped message, because it is read from the session. A stop before the first token leaves an assistant message with no text and the "Stopped" line. A completed turn survives a refresh in the same way: text, sources, meta and feedback state are all read from the stored message.

### Locale key rules (R-151, enforced by the copy scan)

The scan takes every English value, drops the interpolations, and fails any page, component or layout source in which a string literal or JSX text starts with the longest remaining piece (5 characters or more, case-sensitive, followed by anything but a letter, digit, underscore or hyphen). Consequences:

1. New areas and namespaces: `chat`, `assistant`, `retrieval`, `source` (plus `errors.assistant.*`, `nav.chat`). No key is both a string and a parent of other keys.
2. No value may reduce to a bare lowercase word that the code needs as a literal: avoid values such as "{{count}} sources", "{{count}} tokens", "{{count}} chats", "{{count}} messages". The contract uses labelled forms ("Tokens: {{count}}", "Sources") or longer sentences ("{{count}} passages above the threshold"). Query keys, API field names (`chat_id`, `session_id`, `reference`, `finish`), route constants and test ids live in `hooks/`, `services/`, `constants/` or are hyphenated, which the scan does not read or allows.
3. If a value collides with a literal the executor needs, the wording changes, never the gate.

## Accessibility and Quality Floor (additions)

- Status is never colour alone: "Stopped", "No sources found", "Reranked" and the failed line carry an icon and a word; a pressed thumb has `aria-pressed`; the selected rail row has `aria-current` as well as the accent bar.
- **Streaming is not announced token by token.** The message list is `role="log"` with `aria-live="off"`. One sr-only `role="status"` region (polite) announces "Answer started", then "Answer finished", "Answer stopped" or "The answer couldn't be completed". The finished answer is then read by moving to it. The streaming message is `aria-busy="true"` until the final frame.
- The conversation is reachable by keyboard: the list is a focusable scroll container; Tab order inside an answer is pill, pill, code-copy buttons, source chips, thumbs. Esc in the textarea stops a running turn; no other single-key shortcut exists outside inputs.
- Citation pills have a 24px target and an accessible name with the document; the "Sources" row repeats every pill as a 40px target (44px on coarse pointers), so the pill is never the only way in.
- The source drawer and the assistant dialog trap focus, have a title and a description, open with focus on their focal element (the passage box in the drawer, the Name field in the dialog), and return focus to their opener through `onCloseAutoFocus` (the pill or chip that opened it; the "Assistant settings" button; the "Test retrieval"/"View source" button). The alert dialogs do not close on overlay click; default focus is the dismiss button.
- Range fields are native `input type="range"`: label, `aria-valuetext` equal to the readout, arrows, Home, End, Page Up and Page Down native; the readout is also visible text.
- Bounding boxes in the drawer are decorative (`aria-hidden`); the page chips and the "Pages" meta carry the same information in words.
- Everything user- or model-supplied renders as text nodes or through the safe markdown pipeline: no `dangerouslySetInnerHTML`, no `iframe`, no `rehype-raw`, no remote images in answers, links limited to absolute `http:`, `https:` and `mailto:` URLs with `rel="noopener noreferrer"`; relative and fragment links other than `#cite-N` render as plain text. An assistant name, a document name, a passage and a greeting containing markup render as text.
- `prefers-reduced-motion`: static `Loader2`, instant scroll to latest and to a box, no fade on the generating line.
- Contrast: all pairs use inherited tokens; muted meta text stays at 4.5:1 or better on `--background` and `--card`; the foreground thumb on the range track meets 3:1 in both themes.
- A page image, a stream or a feedback call never puts a token in a URL.
- Single-word icon actions carry fuller accessible names and matching tooltips: "Send" is "Send message", "Stop" is "Stop answer".

## Notes for the planner

What the API must return for these screens, and the server-side rules the contract implies. Field names are proposals; shapes are what matter.

1. **Assistant view** (`/api/v1/chats`, `/api/v1/chats/{chat_id}`): `id`, `name`, `icon` (data URL or empty; **detail only**: the list response omits it, choice 31), `permission` (`me` or `team`), `created_by`, `kb_ids` (only the ones the reader can open; the server keeps the others on save, D-25), `unavailable_datasets` (per reader: count of bound datasets this reader cannot open, D-25), `members_with_chats` (detail only, for callers who can manage it: distinct members other than the caller with at least one session; drives the delete confirmation, D-26), `llm_id`, `rerank_id`, `similarity_threshold`, `vector_similarity_weight`, `top_n`, `prompt_config {system, prologue, empty_response}`, `update_time`. Responses say `chat_id` where a key is needed, never `dialog_id` (leak sweep). Names are unique per workspace; a duplicate answers with a reason the SPA maps to the inline error.
2. **Session list and detail**: `id`, `name` (server names a chat after its first question, truncated), `update_time`; detail returns messages newest page first with a way to load earlier ones (50 per page). Message: `id`, `role`, `content`, `created_at`; assistant adds `finish` (`complete`, `stopped`, `failed`; not `status`), `reference`, `usage {input, output, total, estimated}`, `latency_ms`, `empty`, `feedback` (`up`, `down` or null).
3. **Reference chunk**: `index` (0-based, equal to the `##N$$` marker), `chunk_id`, `doc_id`, `doc_name`, `dataset_id`, `content`, `positions [{page, x0, x1, top, bottom}]`, `page_sizes {"<page>": [w, h]}`, `similarity`, `term_similarity`, `vector_similarity`, `rerank_similarity?`, or `{index, unavailable: true}` after read-time redaction. All floats go through `sanitize_floats` (null, never NaN). The SPA never trusts a score or position it cannot parse and omits it.
4. **Completion stream**: delta frames with `final: false`; one frame with `final: true` carrying the canonical `answer`, `reference`, `usage`, `latency_ms`, `finish`, `empty?`; then `[DONE]`; every frame carries `session_id` and `message_id`; pre-stream failures are normal HTTP statuses with the envelope and `data.reason` (names in "Pre-stream refusals"); `Content-Type: text/event-stream`. The final-frame `notice.unavailable_datasets` makes the SPA invalidate the assistant view; no per-answer notice is drawn.
5. **Retrieval test** (`POST /api/v1/datasets/search`): request `dataset_ids [one]`, `question`, `similarity_threshold`, `vector_similarity_weight`, `rerank_id?`, `page`, `size`; response `total`, `chunks` (the hit shape above plus `doc_name`), `rerank_applied`, `timings {embed_ms, search_ms, rerank_ms}`. A dataset with no chunks answers with `total: 0`; the SPA distinguishes "nothing parsed" with the existing dataset summary (`chunk_total === 0`), not a new field.
6. **Reasons** the SPA places by status plus `data.reason`: `datasets_unavailable`, `turn_in_progress`, `session_full`, `model_unavailable`, `rerank_unavailable`, `index_unavailable`, `provider_timeout`, `provider_refused`, `provider_rate_limited`, `assistant_dataset_not_shared` (with offending dataset ids), `assistant_has_member_chats` (with `count`, D-23), duplicate name. A provider failure is never 401 and never envelope code 401 (Phase 3 rule).
7. **Server rules the UI assumes**: a private assistant is listed only to its creator; a session read, delete or completion filters by `chat_id` and `user_id`, and another user's session id is the one 404; an update by the creator, an owner or an admin (D-24) applies dataset changes only to ids the saver can open and keeps every other bound id (D-25); narrowing `team` to `me` is refused with 409 `assistant_has_member_chats` and `data.count` (distinct members other than the creator with at least one session) while that count is above zero, nothing is deleted by a visibility change, and after a successful narrowing the assistant belongs to its creator only (D-23, D-24); a completion for a reader with no usable bound dataset is 409 `datasets_unavailable`, never an empty retrieval (D-25); deleting an assistant (creator, owner or admin only) deletes every member's sessions (D-26); a stored reference is redacted at read time for datasets the reader can no longer open; the opening message is derived from `prompt_config.prologue`, not stored; a stop persists the partial answer with `finish: "stopped"` and an estimated `usage`.
8. **Document detail for the drawer** reuses the Phase 4 route (`pages_total`, `preview`); a 404 is expected and handled. `documentViewerPath(datasetId, docId, page?)` gains the optional `page`; `chunkPath` is unchanged.
9. **Frontend rules to carry into plans**: FE-01 to FE-04, FE-06, FE-07 as above; the copy-scan rules; accessible names are declared for every single-word action ("Send" is "Send message", "Stop" is "Stop answer", "Details"); every announcement and document title has a key; every route gets its registry entry and `nav` where stated; Vitest `server-areas` get `chat`, `assistant`, `retrieval` and `source` areas.
10. **Package checkpoint outcomes** (Open Question 3 of RESEARCH) change only the three rows in "Registry Safety"; no screen layout depends on them.
11. **Record in `.planning/DECISIONS.md`**: the routes (choice 1), draft chats and auto-selection (3), deletion placement (4), avatar as a data URL (6) and `icon` omitted from the list (31), the visibility rule exception (7), no remote images in answers (11), plain-text relative and fragment links (32), retrieval test on request only (21), the D-23..D-26 server rules as built, and the UI-22, UI-25 and RETR-16 Partial hand-offs. UI-22 stays **Partial**: no `remark-math`, `rehype-katex` or `rehype-raw` (so no KaTeX and no raw HTML), no syntax highlighting, no image popovers. Also record the pin deviations from the CLAUDE.md baseline: `eventsource-parser` 4.1.2 instead of 1.1.2, and `react-markdown` 10.1.0 instead of 9.1.0. Both stay behind the D-21 human checkpoint; if either is declined, the fallback in "Registry Safety" applies and no deviation is recorded.

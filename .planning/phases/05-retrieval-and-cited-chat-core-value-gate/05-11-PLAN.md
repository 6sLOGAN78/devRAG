</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client to `/api/v1/chat/completions` | untrusted question, ids |
| retrieved chunk text to the model | prompt injection surface |
| API to the chat provider | question and context leave the system, key goes with it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-11-01 | Information disclosure | answering from a dataset the asker cannot open | mitigate | `resolve_for_chat` per reader; none usable is 409; teammate test after a dataset flips to `me` |
| T-05-11-02 | Information disclosure | reading or continuing another member's session | mitigate | session lookup filters `user_id`; one 404 body; invoker proves it |
| T-05-11-03 | Denial of service | spend exhaustion | mitigate | rate guard, question and session caps, `max_tokens` clamp through `sanitize_llm_setting`, turn lock |
| T-05-11-04 | Tampering | prompt injection in chunks | mitigate | plan 05-10 prompt rules, canonical output, no tools, renderer limits (plan 05-17) |
| T-05-11-05 | Information disclosure | key, question or chunk text in logs and bodies | mitigate | ids and class names only; leak sweep and key scan include the row; usage log fields avoid `token` |
| T-05-11-06 | Tampering | stuck lock or half-written message after a failure | mitigate | `finally` release on every path, owner-checked, TTL backstop, idempotent persistence |
| T-05-11-07 | Repudiation | answer without a record | mitigate | user message stored first, assistant message always stored (complete, failed or empty) |
</threat_model>

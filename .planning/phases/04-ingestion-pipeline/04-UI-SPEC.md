# Phase 4 — UI Design Contract

> Visual and interaction contract for Phase 4 screens. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Mode: non-interactive. The user's standing instruction is "do what you think best for the codebase", so no question was put to them. Every choice that is not traceable to `04-CONTEXT.md` (D-01..D-31), `04-RESEARCH.md`, `03-UI-SPEC.md` (and through it 02 and 01) or `docs/02-frontend/` is marked **(auto-selected)** with a one-line reason and collected in "Auto-Selected Choices".

## Scope and inheritance

This phase INHERITS `03-UI-SPEC.md` and, through it, `02-UI-SPEC.md` and `01-UI-SPEC.md`, including all three sets of Checker Flags. Nothing below redefines a token. Inherited and unchanged:

- Spacing scale 4/8/16/24/32/48/64 and the layout exceptions (header 56px, sidebar 240/64px, 40px targets, 44px coarse-pointer targets, 1280px content max, input height 40px, table row minimum 48px).
- Four type sizes (Body 14, Label 12, Heading 20, Display 28), two weights (400, 600), Mono 14px for ids and machine text. `tailwind.config.ts` compiles only `text-xs`, `text-sm`, `text-xl`, `text-display`.
- Teal-on-slate palette in light and dark, 60/30/10 split, destructive and `--success` tokens. No new colour token.
- `StandardLayout`; `EmptyState`, `ErrorState`, `RouteSkeleton`, `PageHeader`; the Forms contract; the destructive-confirmation convention (default focus on the dismiss button, "Keep {noun}" / "{Verb} {noun}"); sonner rules; sentence case, no exclamation marks; dates through `Intl.DateTimeFormat(i18n.language, …)`; counts through i18next plurals.
- Phase 3 rules learned in code: controls a caller may not use are absent, not disabled; the shared `AlertDialog` is never stacked over a `Dialog` or a `Sheet` (R-152); a controlled dialog with no trigger gets `onCloseAutoFocus` from its owner; menus that open a dialog are non-modal; every workspace-scoped query key starts with `["ws", tenantId, …]`.

Routes. `docs/02-frontend/routing.md` lists only `/dataset/files`; `pages.md` names the folders `chunk` and `document-viewer` without paths. The reference implementation uses `/chunk` and `/document/:id`. This contract uses `/chunk` and `/document` with ids as search parameters, as `/dataset/files` already does **(auto-selected: reference path names, Phase 3 id convention)**, and adds `/dataset/logs` inside the documented `/dataset/*` family **(auto-selected: the log needs a table and paging; no tabs primitive is installed)**. None of the three has a `nav` entry. The sidebar marks "Datasets" active on all of them: `NESTED_PREFIXES["/datasets"]` gains `/chunk` and `/document`, each matched as the exact path or the path followed by `/` or `?`, never as a bare prefix (so a later `/chunks…` or `/documents…` route is not captured).

Source layout follows `docs/02-frontend/knowledge-base-ui.md`, `components.md` and `pages.md`: `pages/dataset/` (extended), `pages/dataset/logs/`, `pages/chunk/index.tsx`, `pages/document-viewer/index.tsx`, `components/chunk-method-dialog/`, `components/parse-configuration/`, `components/document-preview/` (page image, box overlay, page and zoom controls, text preview), hooks in `hooks/use-document-request.ts` (parse, cancel, switch, detail, logs) and a new `hooks/use-chunk-request.ts`.

Not in this phase (no control, no disabled stub, no "coming soon" text other than the two places D-13 and D-15 require): retrieval testing; OCR, layout or table settings as working controls; the other seven chunkers as selectable options; chunk deletion; chunk keyword or question fields; keyword highlighting inside chunk text; text selection on the page image; boxes for chunks other than the selected one; automatic parsing after upload; applying chunking settings to several documents at once; a download or preview of page images outside the app; audio or EPUB preview.

## HTTP client rules for this phase

| Request | Client timeout | `silent` | Notes |
|---------|----------------|----------|-------|
| Lists and details (documents, chunks, document detail, summary, logs) | 10s (existing default) | yes; rendered in place | `placeholderData: keepPreviousData` on every paged or filtered query (FE-01) |
| Parse, parse again, cancel, document on/off | 30s | yes | Parse again removes old chunks from the index first; document on/off rewrites every chunk of the document |
| Save chunking settings | 10s | yes | |
| Edit a chunk, add a chunk | 45s | yes | The server embeds before it saves; its own embedding limit is 30s |
| Chunk on/off | 10s | yes | No embedding call |
| Page image, image file preview | 30s | yes | `responseType: "blob"` |
| Download the original | none (`timeout: 0`) | yes | `responseType: "blob"`, `AbortController`, aborted on unmount |

**Images are fetched, not linked.** The session token travels in the `Authorization` header, so an `<img src>` pointing at an API route would be sent without it. Page images, an image file's preview and downloads are requested through `services/http.ts` as blobs; the component shows `URL.createObjectURL(blob)` and revokes the URL when the page, the document or the component changes. An object URL is created only when the response type is `image/jpeg` or `image/png`. Page-image queries use `staleTime: Infinity` (a stored file never changes) and `gcTime` 60 seconds so at most a few page bitmaps are held. Thumbnails arrive as `data:` URLs inside the document list (below) and are used only when they start with `data:image/jpeg;base64,` or `data:image/png;base64,`.

**Live progress is polling (RESEARCH "Frontend", `docs/02-frontend/state-management.md` "background polling").** No SSE, no WebSocket.

| Query | `refetchInterval` |
|-------|-------------------|
| Documents page of the dataset workspace | 2000ms while any row on the page has `run === "1"`, otherwise `false` |
| Ingestion summary | 2000ms while its own `running` count is above 0, otherwise `false` |
| Document detail in the inspector and the viewer | 2000ms while `run === "1"` |
| Chunk list in the inspector | not on a timer: refetched when the polled document detail reports a different chunk count, and once when `run` leaves `"1"` |
| Parsing details sheet (open) | 2000ms while the entry is running |
| Parsing log page | 2000ms while any row on the page is running |

`refetchIntervalInBackground` stays `false` (a hidden tab does not poll). When a row leaves `"1"`, the dataset detail and the summary are invalidated once so the meta line and totals are current. Parse, cancel and switch mutations invalidate the documents root, the summary and both dataset keys in `onSettled`, not `onSuccess` (FE-03): a request that timed out on the client may still have started on the server.

Server text. The progress message, the progress log, a provider's sanitized refusal and file names are shown as returned, as text nodes, never translated and never as HTML. A server message used inline is limited to 300 characters; longer or empty text uses the fallback copy. The SPA never shows, and the API must never return, a stack trace, a provider key, a storage path or an internal host name (D-08, D-23).

Progress cell:

| State | Content |
|-------|---------|
| Not started | "0%" (unchanged from Phase 3) |
| Parsing | `progress` bar (`aria-label` "Parsing progress for {name}"), "{percent}%" beside it, and under it the latest progress message from the server (Label size, 400, muted, `truncate`, full text in `title`); "Waiting for a worker" when the server has sent none yet |

The percentage is `Math.floor(progress * 100)` capped at 99 while `run` is `"1"`; only `run = "3"` shows 100 (FE-18: `percentOf` must not round 0.996 up).

Row actions (`DocumentRowActions`). The inline button is `outline`, size small; controls for the caller who may change the document:

| State | Inline button (accessible name) | Overflow menu items, in order |
|-------|---------------------------------|-------------------------------|
| Not started, parseable | "Parse" ("Parse {name}") | View chunks; Open document; Chunking method |
| Not started, not parseable | none | View chunks; Open document |
| Parsing | "Cancel parsing" ("Cancel parsing {name}") | View chunks; Open document; Parsing details |
| Finished | none | View chunks; Open document; Parsing details; Chunking method; Parse again |
| Failed, Cancelled, Partly indexed | "Parse again" ("Parse {name} again") | View chunks; Open document; Parsing details; Chunking method |

The menu trigger is a `ghost` icon button `EllipsisVertical`, `aria-label` "More actions for {name}". Every caller who can see the row gets the menu with "View chunks", "Open document" and, once the document has been parsed at least once, "Parsing details"; the other items and the inline button are absent for a caller who may not change the document. "Chunking method" is absent while the document is parsing.

Behaviour:

- **Parse** (D-01): one `POST …/documents/parse` with `run: "1"`. While it is in flight the button is `aria-disabled` and `aria-busy` with `Loader2`. On success the list is refetched and polling starts; no toast (the row shows the change).
- **Cancel parsing**: one request with `run: "2"`, no confirmation **(auto-selected: chunks are kept and "Parse again" undoes it, D-06, D-09)**. On success the row becomes "Cancelled" or "Partly indexed".
- **Parse again**: see "Parse again confirmation". The SPA always sends the request without `confirm_replace` first; the server decides whether a confirmation is needed (D-04, D-09) and answers 409 `confirm_required` with fresh counts.
- **In search** (D-10, D-26): the switch is `aria-busy` and not operable until the server answers, then shows the server's value (not optimistic). No confirmation: it is reversible and changes no chunk's own switch.
- A row whose document vanished (404 on any action): toast "This document no longer exists." and a refetch.

Failures of row actions are error toasts with fixed copy, placed by HTTP status plus `data.reason` in `pages/dataset/errors.ts`:

| Answer | Copy |
|--------|------|
| 400 `parse_unavailable` | Parsing isn't available yet for this file type. |
| 400 `chunker_unavailable` | This document is set to a chunking method that isn't available yet. Choose General, then parse. |
| 409 `already_running` | no toast; refetch (someone else started it) |
| 409 `model_unavailable` | This dataset's embedding model is no longer available in the workspace. Add it again in model settings, then parse. |

| Answer | Reason line |
|--------|-------------|
| 502 / 504 `provider_timeout`, client timeout | The embedding provider timed out. |
| 400 `provider_refused` | The embedding provider refused the text. (plus the server's sanitized reason, at most 300 characters) |

| 409 `model_unavailable` | This dataset's embedding model is no longer available in the workspace. |
| 400 `chunk_too_long` | This text is longer than the embedding model accepts. Shorten it or split it into two chunks. |
| 503 `index_unavailable` | The search index isn't available right now. |

### Locale key rules (R-151, enforced by the copy scan)

The scan in `no-hardcoded-copy.test.ts` takes every English value, drops the interpolations, and fails any page, component or layout source in which a string literal or JSX text starts with the longest remaining piece (5 characters or more, case-sensitive, followed by anything but a letter, digit, underscore or hyphen). The consequences for this phase:

1. No key starts with `documents.` or `document.`; no new top-level namespace is named `chunks`, `chunk`, `tokens`, `pages` or `parse`. New namespaces are `datasets.parse`, `datasets.reparse`, `datasets.details`, `datasets.chunking`, `datasets.ingestion`, `inspector` and `viewer`; `datasets.files` is extended.
2. The values "{{count}} chunk", "{{count}} chunks" and "Chunk {{n}}" exist, and "Parse {{count}} document" reduces to `document` as the Phase 3 values already do, so no source under `pages/`, `components/` or `layouts/` may contain a string literal or JSX text that is exactly `chunk`, `chunks`, `Chunk` or `document`, or that starts with one of them followed by a dot, slash, space or quote (Phase 3 used `"doc"` for the same reason). Query keys, API field names and route constants live in `hooks/`, `services/` and `constants/`, which the scan does not read. Test ids such as `chunk-card` are unaffected.
3. No value may reduce to the bare word `tokens`, `datasets`, `dataset`, `status`, `models`, `upload`, `errors`, `common`, `inspector` or `viewer` (existing or new namespaces). Token totals are therefore a labelled pair ("Tokens" / number), never "{{count}} tokens".
4. No key is both a string and a parent of other keys.
5. If a value still collides with a literal the executor needs, the wording changes, never the gate.

## Accessibility and Quality Floor (additions)

- Status is never colour alone: every badge has an icon and a text; the switch always has the words "On" or "Off"; a switched-off chunk has a badge and a dashed outline as well as muted text; the selected chunk has `aria-pressed` as well as the accent bar.
- Bounding boxes are decorative (`aria-hidden`); the chunk-to-page link is repeated as the card's page chips, the "Page {page} of {pages}" caption and the status announcement.
- Progress uses `progressbar` semantics; one polite status region per page announces state changes, never percentages or every poll.
- Native controls carry the keyboard behaviour: checkbox and switch (Space), radios in the method group and the segmented control (arrows), the scrollable page area and log box (`tabIndex=0`, native scrolling). Single-key shortcuts exist only on a focused chunk header button.
- The alert dialogs (parse again, discard) do not close on overlay click; default focus is the dismiss button; focus returns to the opener, or to the stated fallback when the opener is gone.
- The details sheet and the chunking-method dialog trap focus, have a title and a description, and return focus to their opener through `onCloseAutoFocus`.
- File names, chunk text, file text, progress messages, log lines and provider reasons render as text nodes only. No `dangerouslySetInnerHTML`, no Markdown rendering and no `iframe` anywhere in this phase. HTML files are never shown as markup.
- `prefers-reduced-motion`: static spinner icons, no progress-fill transition, instant scrolling to a box.
- Contrast: all text pairs use inherited tokens. `text-muted-foreground` on `--card` (switched-off chunk text) stays at 4.5:1 or better; nothing is dimmed with opacity. The accent box border meets 3:1 against a white page image in both themes; the 15% fill is not relied on.
- Zoomed page images scroll inside their pane; the page itself never scrolls horizontally at 320px.
- A page image, a thumbnail or a download never puts a token in a URL.

## Notes for the planner

What the API must return for these screens, and the server-side rules the contract implies. Field names are proposals; the shapes are what matter.

1. **Document list rows** (`GET …/documents`) need, besides today's fields: `run`, `progress`, the latest progress message as one line (at most 300 characters, redacted), `chunk_count`, `parseable` (false for types with no parser, D-13), `enabled` (the document's search switch), `thumbnail` (a JPEG or PNG `data:` URL of at most about 16 KB, or null), `last_log_id` (null until the first parse), `pages_total` and `pages_without_text` for PDFs, and for failed documents `error: {step, code, message}`. `error.message` is one plain sentence with no trace, key, path or host name. The latest log row is joined in one batched query for the page, not per row.
2. **Parse and cancel** (`POST …/documents/parse`, body `{doc_ids, run, confirm_replace?}`). `run: "1"` without `confirm_replace: true` must answer 409 with `data.reason = "confirm_required"` and `data.documents: [{id, name, chunk_count, edited_count, manual_count}]` whenever any listed document is finished with chunks (D-04), or failed or cancelled with at least one edited or hand-added chunk (D-09). In that case nothing is started for any id.
3. A parse or cancel request is all or nothing across its ids (permission, visibility, parseability and chunker checks run for every id before any state changes). Accept at least 20 ids (one table page).
4. Refusal reasons the SPA places by status plus `data.reason`: `parse_unavailable` (400), `chunker_unavailable` (400), `already_running` (409), `model_unavailable` (409), `queue_unavailable` (503), `index_unavailable` (503), `parse_running` (409, for settings and chunk writes), `parser_config_invalid` (400, with the field name), `chunk_too_long` (400), `provider_refused` (400, with a sanitized reason of at most 200 characters), `provider_timeout` (502 or 504), `provider_rate_limited` (429 or 503). A provider failure is never 401 and never envelope code 401.
5. **Permission** for parse, cancel, parse again, document settings, document switch and every chunk write is the `can_remove_document` rule with the permission subject (uploader, dataset creator, owner, admin; a token is judged as its user). The dataset default settings use `can_manage_dataset`. Reads (chunks, page images, content, logs, summary) follow dataset visibility. Unknown, foreign and invisible are the one 404.
6. **Document detail** (`GET …/documents/{doc_id}`) needs the list fields plus `parser_id`, the three configurator values (`chunk_token_num`, `delimiter`, `overlapped_percent`), `preview` (`"pages"` when page images exist for this file, otherwise `"none"`), `pages_total`, `suffix` and `size`. The edited and hand-added counts are not needed here; they come with the 409 of note 2.
7. **Document settings** need a write route for one document's `parser_id` and the three values, and one for the dataset default (the dataset update route may carry it). Both validate with the `ParserConfig` model (BE-09); the bounds must equal the form's (chunk size 1 to 8192, overlap 0 to 50, delimiters 1 to 64 characters) or the plan changes the form. The delimiter is a set of characters; the server must not compile user input as a regular expression. Saving settings never re-chunks and never changes `run`. A dataset default change does not touch existing documents.
8. **Chunks list** (`GET …/chunks?page&size&keywords&available`) returns per chunk: `id`, `text`, `positions: [{page, x0, top, x1, bottom}]` (PDF points, origin top left, 1-based pages; empty for formats without geometry and for hand-added chunks), `origin` (`parsed`, `edited`, `manual`), `enabled` (the chunk's own switch, independent of the document's, D-26); and for the response `total`, and `page_sizes: {"<page>": [width, height]}` in the same units for every page referenced. The page image and the boxes must share one coordinate space (same page box and rotation). Order is document order with hand-added chunks last. The keyword filter must survive text such as `what is (revenue` (BE-06). `size` 20.
9. **Chunk writes.** Edit and add embed first and write only on success (D-11); a failure leaves text and vector untouched and says why. An edit sets `origin = edited` unless it is `manual`. Chunk writes and switches are refused with 409 `parse_running` while the document is parsing. The add response returns the new chunk so the SPA can select it. No delete route is needed by this contract.
10. **Switches (D-26).** The document switch and each chunk's switch are stored separately; switching a document back on restores exactly the chunks that were on. Chunks indexed while a document is off must also stay out of search. The chunk DTO reports the chunk's own switch.
11. **Page image** (`GET …/pages/{n}/image`): JPEG or PNG with a correct `Content-Type`, `n` 1-based, 404 beyond the last page, served for any PDF whether or not it has a text layer, `Cache-Control: private`. It is fetched with the `Authorization` header as a blob; no token in a query string. If a Content-Security-Policy is ever set, `img-src` needs `blob:` and `data:`.
12. **Content** (`GET …/content`): the original bytes as an attachment with `X-Content-Type-Options: nosniff`. For the viewer's text preview the SPA needs the file as decoded text (the server already detects the encoding, D-28), at most 262144 characters, with a flag saying whether it was cut; the planner picks the carrier (a `format=text` parameter or a sibling route). HTML is returned as source text and is never served inline as `text/html`. JPG and PNG are returned with their real image type.
13. **Ingestion summary** (`GET …/ingestions/summary`): counts `unstart`, `running`, `done`, `failed`, `cancelled`, `partial` (failed or cancelled with chunks), plus `chunk_total` and `token_total` for the dataset.
14. **Ingestion logs** (`GET …/ingestions?page&size`, newest first, and `GET …/ingestions/{log_id}`): per entry `id`, `document_id`, `document_name`, `started_at`, `duration_seconds`, `status` (`running`, `done`, `failed`, `cancelled`), `attempts`, `max_attempts`, `retried` (false for a failure that was terminal at once), `chunk_count`, `pages_total`, `pages_without_text`, `error: {step, code, message, detail?}`, and on the single-entry route `log` (the progress lines, at most 3000, redacted). `error.step` is one of `queue`, `fetch`, `parse`, `chunk`, `embed`, `index`. The codes the SPA knows are listed in "Parsing details panel"; a new code must come with a plain `message`.
15. **D-14 numbers.** `pages_without_text` and `pages_total` are document-level sums across page-range tasks, available on finished and failed PDFs.
16. **Progress messages and logs are user-facing text.** Write them as plain sentences; the redaction rules (D-23, BE-08) apply before they are stored, not only before they are logged.
17. The 2 second poll means the documents list is requested often while anything is parsing: keep it one indexed query plus the batched log join, with no doc-store call per row.
18. Frontend rules to carry into plans: FE-01 to FE-04 as specified above (including `keepPreviousData` on the existing `useDocumentsRequest`); the copy-scan rules in "Locale key rules"; Phase 3 tests that assert "0%" and "Not started" for unparsed rows still hold; `DocumentStatusBadge`'s "Unknown status" branch stays; accessible names are declared for every single-word action ("Parse", "Details", "Download", "Edit"); every announcement and document title has a key.
19. Record in `.planning/DECISIONS.md`: the three routes (choice 1), server-decided re-parse confirmation (choice 5), all-or-nothing parse requests (choice 8), no chunk delete in this phase (choice 23), blob-fetched images and downloads (choice 29), and the continued non-use of `react-pdf-highlighter`, `pdfjs-dist` and `@tanstack/react-table`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| uploaded file served back to browsers | active content (HTML, SVG, scripts) could run in the app's origin |
| API to pdfium and the temp cache | hostile PDFs reach native code; temp files hold tenant content |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-19-01 | Tampering | stored XSS through `/content` of an HTML or SVG upload | mitigate | HTML is never served as `text/html`; `attachment` except PDF and JPEG/PNG; `nosniff`; `Content-Security-Policy: sandbox`; e2e asserts the headers |
| T-04-19-02 | Information disclosure | page, content or text of another tenant or a private dataset | mitigate | dataset visibility first, found-in-dataset check, the one 404; matrix builders |
| T-04-19-03 | Denial of service | rendering huge pages or flooding the renderer | mitigate | dedicated 2-thread `PDF_EXECUTOR`, 30 s deadline, fixed zoom, one bitmap per request, ETag short-circuit |
| T-04-19-04 | Denial of service | temp cache filling the disk | mitigate | at most 4 files and 400 MiB, eviction deletes, hash-derived names, private directory mode 0700 |
| T-04-19-05 | Tampering | header injection through the file name in `Content-Disposition` | mitigate | `safe_filename` strips quotes, CR, LF and separators; `filename*` encoding |
| T-04-19-06 | Information disclosure | token in a URL | mitigate | images are fetched with the Authorization header by the SPA; the API reads no query token for these routes |
| T-04-19-07 | Denial of service | reading a 100 MiB file into memory for the text preview | mitigate | at most about 1 MiB is read for `format=text`; `content` streams in chunks |
</threat_model>

## Phase Goal

**As a** user waiting for a document, **I want to** have a worker that retries what can succeed, stops when I cancel, hands its work on when it dies and keeps my progress bar honest, **so that** parsing survives crashes, retries and cancellation.

<objective>
Build the executor process: collect and reclaim loop, per-task lock and watcher, retry/terminal/cancel/shutdown handling, the roll-up daemon with the reconciler, the process entry point and its health probe, and prove them in-process against the real MySQL, Valkey, Elasticsearch and a loopback provider.

Purpose: ING-04 to ING-08, ING-10 to ING-12, DOC-12; R-156 to R-158; D-05, D-06, D-14, D-25.
Output: `rag/svr/{executor_loop,heartbeat,progress,task_executor,healthcheck}.py` and three integration suites.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Valkey message to executor | content could be forged or stale |
| executor to MySQL, Valkey, index, provider, storage | failures and outages at every edge |
| executor logs and progress text to users | text reaches the SPA |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-12-01 | Tampering | forged or stale message (other tenant, old digest, deleted task) | mitigate | executor reloads everything from MySQL, drops digest mismatches and gone tasks, never reads tenant or range from the message |
| T-04-12-02 | Denial of service | the same task run by two workers | mitigate | lock gate on every message including reclaimed ones, renewal thread, lost-lock stop, attempt guard, digest, `progress` check; tests for live-owner and displaced-owner cases |
| T-04-12-03 | Denial of service | poison file crashing the worker forever | mitigate | attempts are counted under the lock before the work starts, so a crash consumes an attempt; exhausted tasks fail `worker_lost` |
| T-04-12-04 | Information disclosure | trace, path, key or host in progress lines, log rows or logs | mitigate | failure lines from typed codes only, `redact_text` on every stored line, class names only in logs; tests scan rows and captured logs |
| T-04-12-05 | Denial of service | executor exiting on an outage and leaving documents stuck | mitigate | outage handling never exits; reconciler re-publishes stranded tasks; recovery tests |
| T-04-12-06 | Repudiation | cancel and failure not traceable | mitigate | one `pipeline_operation_log` row per run with status, attempts and structured error |
| T-04-12-07 | Tampering | roll-up overwriting a cancel | mitigate | transition transaction re-checks `run == "1"` under a row lock; cancelled documents are skipped |
</threat_model>

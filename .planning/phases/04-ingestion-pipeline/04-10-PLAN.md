## Trust Boundaries

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-10-01 | Elevation of privilege | an API token or non-uploader member parsing or replacing chunks | mitigate | `can_remove_document` called with `scope.subject`, tested for uploader, creator, owner, admin, normal member and token |
| T-04-10-02 | Information disclosure | probing for another tenant's documents | mitigate | `load_visible_dataset` and the found-count check give the one NOT_FOUND for absent, foreign and private-to-others ids |
| T-04-10-03 | Tampering | data loss when a re-parse is confirmed by accident | mitigate | server decides `confirm_required` with fresh counts; all-or-nothing; nothing deleted before every check passed and the queue answered a ping |
| T-04-10-04 | Denial of service | huge id list or repeated parse | mitigate | at most 100 ids (`ids_invalid`); per-tenant rate limit added at the route in plan 04-14 |
| T-04-10-05 | Tampering | two parse requests racing on one document | mitigate | dataset lock plus row lock and a second `run != "1"` check inside the transaction (`already_running`) |
| T-04-10-06 | Information disclosure | queue or SQL error text in the response | mitigate | typed `ServiceError` with fixed messages; infra errors logged with `type(exc).__name__` only |
</threat_model>
